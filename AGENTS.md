# AGENTS.md

## What this repo is

`subtracker` (working title **Subly**) — an Android-only subscription tracker with Google Sign-In and custom SMTP OTP authentication, a Firestore-backed dual-view dashboard (Calendar + Ledger), on-device trial/renewal reminders, a 35-service cancellation-links directory with automatic fallback merge, brand-curated preset catalog, and a simulated premium paywall.

**Current state:** Fully implemented with 149 tests passing and 0 analyzer issues.
Features include:
- **Auth**: Google Sign-In (`google_sign_in` v7) and Email OTP verification (Brevo/SMTP with 6-digit code).
- **Dashboard**: Dual-mode — interactive Calendar view (renewal clusters, today glow, month navigation) and Ledger view with hero spend ring, 7-day renewal strip, and Quick Filters (`All`, `Renewing Soon`, `Monthly`, `Annual`, `Inactive`).
- **Subscription Lifecycle**: Full active/canceled status tracking. Inactive subscriptions are excluded from spend calculations and reminder schedules, displayed with strikethrough cost and "Canceled" subtitle, filterable via "Inactive" chip.
- **Subscription Actions Modal**: 1-tap modal for Mark Paid / Advance Cycle, Edit, Mark as Canceled / Reactivate, and Delete.
- **Preset Catalog**: 35 curated services with category & search filtering and modern vector brand marks (Canva, Amazon Prime, Adobe CC, Cursor, Claude, Midjourney, 1Password, Google One, Perplexity, etc.).
- **Cancellation Directory**: 35 services with direct cancel links and instructions; automatically merges Firestore documents with built-in defaults so all services are always available.
- **Simulated Paywall**: Free tier limited to 5 active subscriptions; unlock simulated premium for unlimited tracking.

## Architecture

Three-layer (UI → Logic → Data), Riverpod 3-wired:

```
lib/
  main.dart                  Firebase init + ProviderScope with repository overrides
  firebase_options.dart      generated by flutterfire configure (do not hand-edit)
  core/
    config/                  email_config.dart (git-ignored, OTP configuration)
    theme.dart               ALL visual tokens (SublyColors, SublyTypography, SublyMotion, SublySpace)
    brand/brand.dart         SublyMark, BrandBadge, BrandTile, BrandDot
    brand/brand_colors.dart  brand color matching (Netflix red, Spotify green, ...)
    brand/brand_icons.dart   brand vector icon loader and asset mapping
    router.dart              go_router + auth redirect; add routes here only
    notifications/           on-device reminder scheduling
  features/<feature>/
    domain/                  pure logic (date math, totals, CSV) — no Firebase imports, unit-testable
    data/                    repositories, Firestore access
    logic/                   controllers/providers
    ui/                      screens/widgets
```

- Repository providers (`authRepositoryProvider`, `profileRepositoryProvider`, `subscriptionRepositoryProvider`, `cancellationLinkRepositoryProvider`, …) are declared as `Provider((ref) => throw UnimplementedError())` and overridden in `main.dart` with the real implementation. Tests override them with fakes (`fake_cloud_firestore`, `firebase_auth_mocks`).
- `subscriptionsStreamProvider` is auth-aware: it yields an empty stream while signed out (repositories need a uid) so no provider caches an error state from the pre-sign-in frame.
- Reminder sync is event-driven: `reminderSyncProvider` listens to the subscription stream and reconciles on-device reminders on every emission. Only active subscriptions are scheduled.
- Spend calculation (`calculateTotals`): inactive subscriptions (`!sub.active`) are excluded from monthly spend and renewal pace totals.
- Cancellation directory: `CancellationLinkRepository.watchAll()` overlays Firestore documents onto `kDefaultCancellationLinks` so all 35 services remain accessible even if Firestore is unseeded or only partially seeded.
- Firestore model: everything under `users/{uid}` (owner-only rules); shared `cancellation_links` collection (read-only to clients, seeded server-side).
- Tests mirror the layers: `test/domain/`, `test/data/`, `test/logic/`, `test/ui/`, `test/design/`.

## Design system (do not violate)

- **Both themes come from one token sheet** in `lib/core/theme.dart`: `buildSublyTheme(Brightness.dark|light)`. Never hardcode a color, font, or spacing — read `context.sublyColors.*`, `SublyTypography.*`, `SublyMotion.*`, `SublySpace.*`.
- **Monochrome discipline:** ink tiers + surface steps carry hierarchy. Color appears only as brand dots/edges (`brandColorFor`) and muted status tints. Exactly one glow, behind the hero number.
- **Fonts are bundled variable TTFs** (Space Grotesk, Inter as `InterSubly`) — weights come from `fontVariations('wght', …)` via `SublyTypography`; money uses tabular figures. No runtime font fetching.
- **Motion is cinematic calm:** ease-out only, no bounce; durations/curves from `SublyMotion`. Haptics on save/limit/unlock.
- Icons are **flutter_lucide with snake_case names** (`link_2`, `settings_2`, `log_out`, `file_down`, `chevron_right`).
- Dedicated vector SVGs (`assets/brand/logos/`) are prioritized for specific brands (Prime smile, Cursor isometric cube, modern Canva wordmark, etc.).

## Riverpod 3 / Flutter 3.47 gotchas (learned here)

- `StreamProvider.future` resolves only when the stream **completes** — Firestore snapshot streams never do. Never `await someStreamProvider.future`; read `.value` or pass data through listen callbacks.
- `StateProvider` no longer exists — use `NotifierProvider` with a `Notifier`.
- `Switch` uses `activeThumbColor` (not the deprecated `activeColor`); AppBar/Card themes use the `…ThemeData` classes.
- `flutter_local_notifications` v22 takes named args (`initialize(settings:…)`, `zonedSchedule(id:…)`); it requires core-library desugaring (already enabled in `android/app/build.gradle.kts`).
- `google_sign_in` v7: `GoogleSignIn.instance.initialize(serverClientId: kGoogleServerClientId)` MUST run before `authenticate()` — on Android the Web client ID is mandatory for minting an idToken. The ID lives in `kGoogleServerClientId` (auth_repository.dart); it appears in the console only after Authentication is provisioned. Then `FirebaseAuth.signInWithCredential(GoogleAuthProvider.credential(idToken: ...))`.
- Widget tests: `RenderRepaintBoundary.toImage` must run inside `tester.runAsync` (fake-async hangs it); lazily-built ListView children need `scrollUntilVisible`, not `ensureVisible`.
- Form status controls: avoid redundant duplicate controls (e.g. A switch and a button toggling the same state in one card). Use a single unambiguous action button or switch with status indicator.

## Locked constraints (do not violate)

- **Android is the only maintained target.** No iOS/desktop targets or platform-specific code for them.
- **No FCM, no Cloud Functions, no paid Firebase plan.** Reminders are scheduled locally with `flutter_local_notifications` + `timezone` (default: 3 days before the charge at 09:00 local).
- **Billing cycles are `weekly` | `monthly` | `annual` only**, driven by the stored `nextChargeDate` (which equals `trialEndsAt` while trialing). Monthly advancement must clamp month-ends (Jan 31 → Feb 28/29).
- **No FX conversion.** Currency is a per-subscription display field; totals are always grouped per currency.
- **Free tier = 5 active subscriptions**, enforced client-side in `SubscriptionRepository.add` (throws `LimitReachedException` → form routes to `/paywall`). Premium is a **simulated** `premium: bool` on the user doc — no real billing.
- **Firestore security rules (`firestore.rules`) are part of the deliverable**, never left in test mode.
- `scripts/serviceAccountKey.json` must **never** be committed (git-ignored).
- `lib/core/config/email_config.dart` must **never** be committed (git-ignored; copy from `email_config.example.dart`).
