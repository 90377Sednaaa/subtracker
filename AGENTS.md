# AGENTS.md

## What this repo is

`subtracker` (working title **Subly**) — an Android-only subscription tracker with Google Sign-In, a Firestore-backed dashboard, on-device trial/renewal reminders, a seeded cancellation-links directory, and a simulated premium paywall.

**Current state:** the MVP plan has been implemented (see git log on `feat/subly-mvp`); the design plan in `docs/superpowers/plans/2026-09-06-subly-mvp.md`. Read that plan before building any feature; it contains the locked decisions, Firestore data model, file layout, and per-task tests. (`docs/` is currently untracked.)

## Commands

```bash
flutter pub get            # after changing pubspec.yaml
flutter analyze            # MUST be clean before every commit
flutter test               # full suite
flutter test test/domain/renewal_calculator_test.dart   # focused test
flutter run -d android     # run on device/emulator
```

The plan follows strict TDD: write the failing test, run it to confirm it fails, implement, run to green, then commit. Commit after every passing test cycle using Conventional Commits (`feat:`, `test:`, `chore:`, `docs:`).

## Architecture

Three-layer (UI → Logic → Data), Riverpod-wired. Target layout:

```
lib/
  main.dart                  Firebase init + ProviderScope with repository overrides
  firebase_options.dart      generated by flutterfire configure (do not hand-edit)
  core/
    theme.dart               ALL visual design decisions live here
    router.dart              go_router + auth redirect; add routes here only
    notifications/           on-device reminder scheduling
  features/<feature>/
    domain/                  pure logic (date math, totals, CSV) — no Firebase imports, unit-testable
    data/                    repositories, Firestore access, Riverpod providers
    logic/                   controllers/providers
    ui/                      screens/widgets
```

- Repository providers (`authRepositoryProvider`, `profileRepositoryProvider`, `subscriptionRepositoryProvider`) are declared as `Provider((ref) => throw UnimplementedError())` and overridden in `main.dart` with the real implementation. Tests override them with fakes (`fake_cloud_firestore`, `firebase_auth_mocks`) — this is the standard seam; follow it for new repositories.
- Firestore model: everything under `users/{uid}` (owner-only rules); shared `cancellation_links` collection. Field names and shapes are fixed in the plan's "Firestore Data Model" section.
- Tests mirror the layers: `test/domain/`, `test/data/`, `test/ui/`.

## Locked constraints (do not violate)

- **Android is the only maintained target.** `web/` exists from the template but is unmaintained; do not add iOS/desktop targets or platform-specific code for them.
- **No FCM, no Cloud Functions, no paid Firebase plan.** Reminders are scheduled locally with `flutter_local_notifications` + `timezone` (default: 3 days before the charge at 09:00 local).
- **Billing cycles are `weekly` | `monthly` | `annual` only**, driven by the stored `nextChargeDate` (which equals `trialEndsAt` while trialing). Monthly advancement must clamp month-ends (Jan 31 → Feb 28/29).
- **No FX conversion.** Currency is a per-subscription display field; totals are always grouped per currency.
- **Free tier = 5 active subscriptions**, enforced client-side in `SubscriptionRepository.add` (throws `LimitReachedException` → form routes to `/paywall`). Premium is a **simulated** `premium: bool` on the user doc — no real billing.
- **UI is placeholder-grade Material 3 on purpose.** A separate design phase owns `lib/core/theme.dart` and screen composition. Feature widgets must use `Theme.of(context)` styles — never hardcoded colors/typography/spacing.
- **Firestore security rules (`firestore.rules`) are part of the deliverable**, never left in test mode.
- `scripts/serviceAccountKey.json` must **never** be committed; keep it in `.gitignore` when the seed script task lands.
- `google_sign_in` v7 API: `GoogleSignIn.instance.authenticate()` + `account.authentication.idToken`, then `FirebaseAuth.signInWithCredential(GoogleAuthProvider.credential(idToken: ...))`. If the resolved package version differs, follow the package's bundled example but keep the `AuthRepository` contract fixed.
