# AGENTS.md

## What this repo is

`subtracker` (working title **Subly**) — an Android-only subscription tracker with Google Sign-In, a Firestore-backed dashboard, on-device trial/renewal reminders, a seeded cancellation-links directory, and a simulated premium paywall.

**Current state:** both plans are implemented and merged to `main` — the architecture/MVP plan and the design plan (monochrome dark ledger, Space Grotesk + Inter, count-up hero with pace ring, staggered ledger with card-morph, paywall reveal, brand-color accents). 60+ tests green, analyzer clean. Follow-up work and deferred device checks are listed in the README's demo checklist. The plans live in `docs/superpowers/plans/` — read them before building any feature; they contain the locked decisions, Firestore data model, file layout, and per-task tests.

## Architecture

Three-layer (UI → Logic → Data), Riverpod 3-wired:

```
lib/
  main.dart                  Firebase init + ProviderScope with repository overrides
  firebase_options.dart      generated by flutterfire configure (do not hand-edit)
  core/
    theme.dart               ALL visual tokens (SublyColors, SublyTypography, SublyMotion, SublySpace)
    brand/brand.dart         SublyMark (the user's logo, tinted) + BrandDot
    brand/brand_colors.dart  brand color matching (Netflix red, Spotify green, ...)
    router.dart              go_router + auth redirect; add routes here only
    notifications/           on-device reminder scheduling
  features/<feature>/
    domain/                  pure logic (date math, totals, CSV) — no Firebase imports, unit-testable
    data/                    repositories, Firestore access
    logic/                   controllers/providers
    ui/                      screens/widgets
```

- Repository providers (`authRepositoryProvider`, `profileRepositoryProvider`, `subscriptionRepositoryProvider`, …) are declared as `Provider((ref) => throw UnimplementedError())` and overridden in `main.dart` with the real implementation. Tests override them with fakes (`fake_cloud_firestore`, `firebase_auth_mocks`) — this is the standard seam; follow it for new repositories.
- `subscriptionsStreamProvider` is auth-aware: it yields an empty stream while signed out (repositories need a uid) so no provider caches an error state from the pre-sign-in frame.
- Reminder sync is event-driven: `reminderSyncProvider` listens to the subscription stream and reconciles on-device reminders on every emission. Don't call reconcile from screens.
- Firestore model: everything under `users/{uid}` (owner-only rules); shared `cancellation_links` collection (read-only to clients, seeded server-side). Field names and shapes are fixed in the plan's "Firestore Data Model" section.
- Tests mirror the layers: `test/domain/`, `test/data/`, `test/logic/`, `test/ui/`, `test/design/` (tokens + screenshots + icon generation).

## Design system (do not violate)

- **Both themes come from one token sheet** in `lib/core/theme.dart`: `buildSublyTheme(Brightness.dark|light)`. Never hardcode a color, font, or spacing — read `context.sublyColors.*`, `SublyTypography.*`, `SublyMotion.*`, `SublySpace.*`.
- **Monochrome discipline:** ink tiers + surface steps carry hierarchy. Color appears only as brand dots/edges (`brandColorFor`) and muted status tints. Exactly one glow, behind the hero number.
- **Fonts are bundled variable TTFs** (Space Grotesk, Inter as `InterSubly`) — weights come from `fontVariations('wght', …)` via `SublyTypography`; money uses tabular figures. No runtime font fetching.
- **Motion is cinematic calm:** ease-out only, no bounce; durations/curves from `SublyMotion`. Haptics on save/limit/unlock.
- Icons are **flutter_lucide with snake_case names** (`link_2`, `settings_2`, `log_out`, `file_down`, `chevron_right`).
- The launcher icon derives from the user-authored SVG in `assets/branding/` (original untouched; derived files are generated).

## Riverpod 3 / Flutter 3.47 gotchas (learned here)

- `StreamProvider.future` resolves only when the stream **completes** — Firestore snapshot streams never do. Never `await someStreamProvider.future`; read `.value` or pass data through listen callbacks.
- `StateProvider` no longer exists — use `NotifierProvider` with a `Notifier`.
- `Switch` uses `activeThumbColor` (not the deprecated `activeColor`); AppBar/Card themes use the `…ThemeData` classes.
- `flutter_local_notifications` v22 takes named args (`initialize(settings:…)`, `zonedSchedule(id:…)`); it requires core-library desugaring (already enabled in `android/app/build.gradle.kts`).
- `google_sign_in` v7: `GoogleSignIn.instance.initialize(serverClientId: kGoogleServerClientId)` MUST run before `authenticate()` — on Android the Web client ID is mandatory for minting an idToken. The ID lives in `kGoogleServerClientId` (auth_repository.dart); it appears in the console only after Authentication is provisioned. Then `FirebaseAuth.signInWithCredential(GoogleAuthProvider.credential(idToken: ...))`. Keep the `AuthRepository` contract fixed.
- Widget tests: `RenderRepaintBoundary.toImage` must run inside `tester.runAsync` (fake-async hangs it); lazily-built ListView children need `scrollUntilVisible`, not `ensureVisible`.

## Locked constraints (do not violate)

- **Android is the only maintained target.** No iOS/desktop targets or platform-specific code for them.
- **No FCM, no Cloud Functions, no paid Firebase plan.** Reminders are scheduled locally with `flutter_local_notifications` + `timezone` (default: 3 days before the charge at 09:00 local).
- **Billing cycles are `weekly` | `monthly` | `annual` only**, driven by the stored `nextChargeDate` (which equals `trialEndsAt` while trialing). Monthly advancement must clamp month-ends (Jan 31 → Feb 28/29).
- **No FX conversion.** Currency is a per-subscription display field; totals are always grouped per currency.
- **Free tier = 5 active subscriptions**, enforced client-side in `SubscriptionRepository.add` (throws `LimitReachedException` → form routes to `/paywall`). Premium is a **simulated** `premium: bool` on the user doc — no real billing.
- **Firestore security rules (`firestore.rules`) are part of the deliverable**, never left in test mode.
- `scripts/serviceAccountKey.json` must **never** be committed (git-ignored).
- `lib/core/config/email_config.dart` must **never** be committed (git-ignored; copy from `email_config.example.dart`).
